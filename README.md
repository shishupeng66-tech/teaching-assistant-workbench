# 教学辅助工作台

教师本机使用的独立教学管理系统。当前版本 **0.3.0 / 第三阶段：教材目录驱动的题库与知识点系统**。

第一、二阶段已经项目所有者亲自验收。本阶段只授权题库与知识点系统，完成后等待所有者实际操作验收；第四阶段及后续未授权。

## 当前可以做什么

- 创建、修改、切换和归档班级，设置学年、年级与编号，查看人数及归档班级。
- 新增、编辑、搜索学生，使用 Excel 模板预览与批量导入，学生转班、归档、查看永久 ID 与归属历史。
- 设置教室行列，拖拽分配和交换座位，或点击座位后选择学生；明确保存，刷新/重启后保持。
- 点击座位或学生名进入详情，查看资料、当前班级、座位、学年归属历史和基础操作记录。
- 深浅主题、折叠导航、数据库状态、真实备份与安全恢复。
- 教材目录、统一知识点、八类题目、富文本公式图片、Excel导入、审核、相似提示、版本快照及范围统计已实现。
- 试卷库、考试、AI分析与组卷仍未开发，入口禁用或明确占位。

默认数据库不含演示班级或学生，所有业务信息来自后端。测试使用独立临时实例，不混入所有者数据。

## 教材目录驱动的题库（第三阶段）

1. 点击“题库 → 教材目录管理”，手动创建学科（可从化学开始）、教材版本、年级/册别、章/节/课时。没有预填未经核实的出版社目录。
2. 进入“知识点主库”建立独立知识点、编码和说明，设置上级/前置/相关关系，并映射到同学科不同教材版本的多个章节。
3. 返回题库选章节，右侧查看知识点、题量和分布；勾选“包含全部下级章节”切换范围，题目去重计数。全局搜索或“全部题目”跨教材检索。
4. 新增题目：选择学科、年级、八种题型之一、1–5难度，填写题干、答案、解析与来源，勾选多个知识点和章节。小问/权重/评分依据为后续扩展结构，不计算考试成绩。
5. Tiptap支持文字、上下标、表格；“公式 / 化学式”用LaTeX/mhchem，例如 `\ce{2H2 + O2 -> 2H2O}`、`\ce{SO4^2-}`。渲染与字体全部本机加载。图片通过上传持久保存于数据目录assets，不依赖浏览器缓存。
6. 保存为草稿，提交待审核，再由教师明确通过。编辑已审核题会退回草稿，原版本与审核保留。相似题仅作提示，需教师确认，不自动合并。
7. 批量题目导入使用系统12列.xlsx模板，先预览错误/相似，教师确认后保存草稿。章节路径只匹配既有唯一节点，未知或歧义须修正，绝不自动猜测。
8. 目录导入使用4列模板，父路径须已有或一并列出，输入“目录已审核”后保存；已有节点只跳过，不覆盖。两种导入均最多500条、5MB，不接受Excel公式、宏、外链或嵌入图片。图片可在导入后用编辑器上传。

详细数据模型：docs/phase-03-data-model.md；交付报告及逐项验收：docs/phase-03-report.md、docs/phase-03-acceptance.md。章节说明默认折叠，点击“教学目标与章节说明”可查看；后续工具展开后仍为禁用状态。

## 创建第一个班级

点击班级页右上角 **新建班级**，填写名称、学年、年级及编号并保存。顶部下拉切换班级；同名班级用学年、编号和短 ID 区分。班级设置可修改资料或在输入确认文字后归档。勾选“查看已归档班级”可查看归档数据；归档不删除学生和历史。

修改班级学年、年级或编号时，为在班学生结束旧历史段并建立新段，座位保持；仅改名不会覆盖入班时的班级名称快照。

## 学生和座位

在教室下方“班级学生”区域点击 **添加学生**，姓名必填，其余可选。永久 ID 由系统生成，不随转班和学号变化。同名不自动合并。当前第一版将非空学号视为全系统唯一（含归档学生），请不要把班内重复的座位号当作学号；无统一学号可留空。

点击 **安排座位**，设置 1–12 行/列，点击座位后从选择框指定学生，或拖动名册学生到座位。将已排座学生拖到另一已占用座位会交换；选择已排座学生也可交换。选“空座位（清空）”释放该座位。点击 **保存座位布局** 才会写入，取消不会保存。缩小行列前须先清空范围外座位；不会默默丢弃学生座位。

正常浏览时点击学生座位或名册姓名进入详情。在详情可编辑、转班及归档；转班自动释放旧座位，归档保留历史。学生管理可跨班级搜索及查看归档学生。归档在本阶段为只读，不提供取消归档或删除档案。

多页面同时排座时采用版本检查；冲突会报错而不覆盖，请点击“重新载入”再安排。

## Excel 导入

班级学生区域 → **Excel 导入** → 下载模板。只填写“学生导入”工作表，保持五列表头：姓名、学号、性别、入学年份、备注。目标班级由当前页面确定，不填入 Excel。

- 只支持 `.xlsx`；最多 5MB、1000 行；不接受宏、外部链接或公式。学号应为文本，以保留前导零。
- 姓名必填；性别可空或男/女/其他；年份为 1900–2100 整数；备注最多 2000 字。
- 先 **校验并预览**，查看行号、错误和重复提示，再确认导入。
- 错误须修正后重新上传；重复可整批拒绝，或跳过重复只导入其余有效行。不会覆盖或合并已有档案。
- 文件内重复学号/完全相同记录、系统已有学号会提示；同名不同学号可分别建档。
- 同一个二进制文件再次导入同班级返回原批次，不重复新增。无学号文件另存或修改后无法可靠识别同一人，务必人工核对；不会按姓名合并。

## 存储、迁移与恢复

默认数据：`~/Library/Application Support/TeachingAssistantWorkbench/data`；独立备份：`~/Library/Application Support/TeachingAssistantWorkbench/backups`。

可复制 `.env.example` 为 `.env`，或在终端导出 TAW_DATA_DIR / TAW_BACKUP_DIR 指向两个全新独立的绝对路径。不能相同、嵌套或包含符号链接。环境变量优先于 .env。禁止指向旧系统数据目录；非空未知目录、未知数据库会被拒绝。

第三阶段 Alembic 从 0002 增量升级到 **0003**（也兼容从0001升级）；升级既有数据库前自动生成并校验 before-migrate 副本，事务内建表，不清空旧库。裸 Alembic 命令被禁止；手动迁移须在 backend 目录设置同样的环境变量，再运行 `.venv/bin/python -m app.manage migrate`（手动命令不自动读取根 .env）。

设置页 **创建备份** 使用 SQLite 一致副本并做完整性、实例、版本及外键校验。0003备份还会生成同名 `.sqlite3.assets` 文件夹，含图片与校验清单，必须和数据库成对保管。恢复校验源附件，补齐不可变图片后原子发布数据库；不删除较新图片以保护历史和恢复前副本。恢复须输入“恢复当前工作台”；先保留 before-restore 副本，再校验临时副本并原子替换。0001/0002 的同实例旧备份也可恢复，系统在临时副本上先升级到 0003，源备份不变。恢复旧备份代表返回当时数据状态，之后的数据及操作记录留在恢复前副本，可再次恢复该副本回退。

业务审计保存在 audit_logs；迁移/恢复事件另追加到数据目录 storage-events.jsonl，不随数据库恢复回滚，关联恢复源和恢复前副本。备份只在本机，未提供加密、异地备份、自动轮转、跨实例导入或灾难恢复。

## 自测（不替代用户验收）

先关闭本项目当前实例，测试拒绝复用用户服务，始终使用新建临时目录：

```bash
./scripts/check.sh
cd frontend
npm run format:check
npm audit
npm audit --omit=dev
```

首次缺少测试浏览器可在 frontend 运行 `npx playwright install chromium`。检查包含后端、类型、构建、13 项 Playwright 浏览器流程以及实际进程两轮重启的数据保留验证。后端独立检查：在 backend 运行 `.venv/bin/python -m pytest -q`。后端格式检查：`.venv/bin/ruff format --check app migrations tests`。

固定依赖为 package-lock.json、uv.lock、requirements-dev.txt；setup.sh 使用 npm ci、uv sync --frozen，或 venv/pip。完整 npm audit 当前仍有 5 个开发工具链高危条目，详情见阶段报告；生产依赖审计为 0，不表示系统绝对安全。

## 项目结构和文档

- frontend/src/pages：五项业务页面、学生详情和系统设置。
- frontend/src/features/library：目录树、知识点、富文本、公式、图片、导入与关联。
- frontend/src/features/classes：班级/学生抽屉、目录、Excel 导入、操作记录。
- backend/app/core：配置、SQLAlchemy 实体和请求模型。
- backend/app/services：事务、班级/学生规则、座位、导入与安全存储。
- backend/app/api：健康/设置/备份与班级管理 API。
- backend/migrations：0001基础、0002班级、0003目录/知识点/题库增量迁移。
- tests、backend/tests：隔离工程自测；scripts：统一安装、启动与检查。
- docs/architecture.md：现有架构与后续扩展边界。
- docs/phase-03-report.md、docs/phase-03-acceptance.md：中文交付报告和人工验收步骤。

本地 Git 无远程仓库。数据库、密钥、Excel 原始名单和日志不纳入 Git。最终验收权仅属于项目所有者；第三阶段交付后停止，第四阶段尚未授权。
